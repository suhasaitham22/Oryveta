# Branding and domain decisions

## Locked product identity

**Oryveta** (previous working name: MASGENT). Brand statement: **Build thoughtfully. Evolve continuously.** Both the brand statement and any short tagline are secondary to a plain explanation of what the product does; see [Voice and wording](#voice-and-wording). Public-facing copy should lead with the Home eyebrow **Open-source software delivery**, the heading **Build new apps. Improve your code.**, and the footer **Plan software. Review source. Work together.** The earlier **Build. Experiment. Prove.** tagline is retired from product copy.

Two primary entry points: **Start New** and **Evolve**. The current visual direction is the original orbital studio system: off-white public/product surfaces, a dark working rail and cobalt accents; see [DESIGN-SYSTEM.md](DESIGN-SYSTEM.md). Avoid names that imply Kaggle-only functionality.

## Domain

Current hosted product: https://oryveta.vercel.app. This Vercel alias serves the React Studio; production authentication and collaboration verification are recorded in [STATUS.md](STATUS.md). A deployed frontend does not establish that a cloud coding worker is running.

Earlier Namecheap checks reported oryveta.com available around $10.98 for the initial year and oryveta.xyz around $2 first year; these are **historical quotes**, availability/prices can change and domains renew rather than transfer ownership forever. No Oryveta paid domain purchase has been made.

## Voice and wording

Say what the product does before anything stylish. A slogan never replaces the one-sentence explanation: *Oryveta is an open-source software delivery workspace, being built into an AI software factory.* Wherever a reader first lands, name the audience — individual builders, developers, consultants and teams — and the two entry points: **Start New** for a new application, **Evolve** for an existing application or package. Keep both names spelled exactly that way.

Write input → action → output, and lead with the concrete task and its value. Prefer **app**, **code**, **project brief**, **source findings**, **demo script** and **private conversation** over intent, artifact, handoff and proofloop jargon. The three example documents are named **Project brief**, **Code review** and **Demo script** everywhere they appear.

State what is available and what is planned once, in a clear section, instead of hedging every sentence. Label planned capabilities as planned: agents that implement, test and repair code, repository publication, on-call response, learned skills and enterprise operation are goals, not features. Distinguish hosted collaboration from self-hosted analysis when a capability only exists in one of them. No superlatives, and no invented availability, model results, benchmark scores or uptime.

## Brand expression

Off-white surfaces, cobalt actions, self-hosted Geist typography and restrained original orbital graphics. SVG provides immediate dimensional artwork; an optional spatial viewer adds real 3D without slowing the initial page. Working screens prioritize the current project, conversation, recorded task and result. Preserve readable static alternatives, live reduced-motion support and strong contrast; avoid excessive glass effects, fictional dashboards and inflated AI claims.
