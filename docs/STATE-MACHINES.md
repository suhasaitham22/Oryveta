# State machines and lifecycle contracts

## Decision

Keep state explicit at its existing authority boundary, not in one global machine. PostgreSQL owns hosted grants and durable work; SQLite owns the separate local engine; operator-owned repair controllers own execution and private evidence; React owns observation, selection and unsaved intent. No new state-machine framework, queue, identity authority or wire-status migration is required.

Every change must answer four separate questions: **what happened to the work, what this observer knows, what the evidence proves, and who may act next**. A failed read is not empty data; a successful attempt is not approval; a retained identity is not permission. Models and browser controls cannot supply authorization.

Use existing local request-generation/liveness patterns and transaction-local SQL guards. Introduce a reducer or selector only when it removes demonstrated contradictory states. Do not move fencing or multi-row SQL predicates into an application-only transition helper. Unknown future wire values must not be guessed into success or permission.

## Non-negotiable invariants

1. **Identity is not authority.** Hosted sign-in, project rights, private-chat rights, worker designation, repair policy and local-engine identity remain distinct.
2. **One writer per durable fact.** Browser state and child-process output do not overrule SQL work/run state. SQL success does not certify a merge/deploy.
3. **Work item is not attempt.** A failed/expired attempt can leave a work item queued for another bounded attempt. Retry recomputes; it does not resume a model trajectory.
4. **Cancellation is not one universal operation.** Local SQLite cancellation fences persistence even if computation continues; supervised durable workers also stop child process groups. Neither permits a late result to resurrect canceled work.
5. **Unknown is not empty or successful.** A failed poll is observer failure, not proof that no work exists. Keep protected data cleared when access is uncertain; never preserve stale sensitive data unconditionally.
6. **Verification is not approval.** `succeeded`, `verification=passed`, `needs_review` and `publication=not_requested` answer different questions. No implicit approve/apply/push/merge/deploy transition exists.
7. **History is not permission.** Deleted actor attribution, immutable worker identity and historical accepted invitations are not reusable grants.
8. **Unknown usage is not free usage.** Preserve pending reservations across interruption and charge uncertain local-gateway usage conservatively; terminal settlement is not refundable by a late response.
9. **Newer intent wins.** A response must still match its owner, workspace/project/chat/item/run and request generation. A save acknowledgement clears only the submitted draft, not text typed later.
10. **Evidence identity stays pinned.** Source commit/tree, configuration, checks and candidate identities must agree; an artifact or a model's final message cannot independently establish successful publication.


## Contract for subsequent changes

For a changed boundary record: current state, event, authority/guard, side effect, resulting state, reason code and next actor. Reuse stable existing API fields and error codes. Keep work identity, attempt/run identity, status, phase, verification scope, publication and observation freshness separate. Derive available actions from current server-authorized facts; do not trust a client read model as a new grant.

| Dimension | Required evidence | Reject |
| --- | --- | --- |
| UX | Correct selection and current facts; actionable loading/failure/recovery; newer drafts survive old acknowledgements | False progress, fabricated emptiness, stale private data or implicit approval |
| DX | One owner per fact; existing generation, cancellation and transaction patterns; bounded source changes | Another store, queue, framework, global helper or duplicated authority without a demonstrated need |
| AX | Stable identifiers/reason codes; unambiguous admissible actions; explicit idempotency and evidence boundaries | Inferring permission from labels, retrying terminal refusals, resubmitting an uncertain acknowledgement or self-approval |
| Compatibility | Real before/after scenario, existing consumer flows, unchanged auth/wire/lease/receipt semantics | Tests that assert source text or labels instead of behavior; green builds presented as production proof |

A supported local job uses `canceled`; durable work uses `cancelled`. Normalize presentation, not stored/wire values. Preserve exact current cancellation and retry semantics. Keep private tokens, credentials, prompts, expected values and operator paths outside browser-facing observations.

The frozen repair policy, current authorization and live lease remain necessary for publication even after a local candidate passes checks. Cancellation/revocation can discard that candidate; respecting authority takes precedence over retaining apparent success. Recompute-on-retry has a compute cost but is not resumable model execution. These tradeoffs cannot support a universal zero-breakage or always-improves-every-metric promise.

## Regression boundaries

- A policy-fetch transport failure must show the read error without claiming no policy is enrolled. Successful empty reads can show enrollment guidance. Keep protected data cleared and queueing disabled when authority cannot be observed. `scripts/factory_runtime_ui_smoke.py` exercises failure and recovery against real local Auth/PostgREST, aborting only the failed network request.
- A response belongs to its current owner/context/request generation. A delayed list/detail/error must not replace a newer route, selection or acknowledged mutation. Preserve current intentional new-record selection rather than silently choosing the first record.
- A mutation acknowledgement clears only the draft it submitted. A component that no longer owns the context cannot rewrite shared intent. Scope UI feedback to the operation's originating page and record.
- Workspace regression cases cover old list success and failure, acknowledged creation, consumed drafts, and save/create acknowledgements after the instance is abandoned. The legacy regression covers late lists/details/errors and preserves current-request error reporting. These protections do not convert browser intent into server authorization.
- Browser closure and request failure do not cancel durable work. Cancellation/reclaim/revocation must fence old results and leave review/publication semantics unchanged.

Use the existing browser collaboration/local-engine smoke entrypoints and [QUALITY.md](QUALITY.md) gates. Exercise transport failure separately from permission revocation and missing schema; do not fabricate successful responses or preserve stale private data to hide an error. A real isolated local smoke is not production OAuth, hosted execution, complete accessibility certification or a repair-quality benchmark.
